<TaskMeta time="30分" level="発展" credentials="Judge用Agent認証" cost="3判定 × 対象回答" />

LLM Judgeは、数値の正誤を雰囲気で採点するためのものではありません。決定的ゲートを通った回答だけを対象に、コードでは決めにくい説明品質を4次元で評価します。

<Steps>

1. ### Judgeのrubricを作る

   `workshop/manual/prompts/judge-v1.md`を作ります。

   ```markdown
   # Semantic quality judge

   AWSコスト見積もりの説明品質だけを評価する。
   数値・Schema・必須サービスは別のコードで検査済みであり、ここでは再採点しない。
   回答を作ったmodelやprofileを推測せず、長さを品質として評価しない。

   次の4次元を1〜5で採点する。
   1. assumption_clarity: 仮定が明示され、費用への影響と結び付いている
   2. uncertainty_handling: 曖昧さを認識し、必要なら質問している
   3. exclusion_clarity: 除外した費用と境界が理解できる
   4. actionability: 第三者が再計算・反証・更新できる

   全次元3以上かつcritical concernがない場合だけsemantic_pass=trueにする。
   `judge-input.json`と`repeat.txt`を読み、item IDとrepeat番号を出力へ写す。
   `judge-output.schema.json`に従うJSONだけを返す。
   ```

2. ### Judge出力のSchemaを用意する

   <Command title="Judge契約を準備">

   ```bash
   cp schemas/judge-output.schema.json \
     workshop/manual/schemas/judge-output.schema.json
   python -m json.tool \
     workshop/manual/schemas/judge-output.schema.json > /dev/null
   ```

   </Command>

3. ### 回答を匿名化する

   Judge workspaceには、case ID、model名、Agent CLI、MCP有無、成功率を入れません。採点対象の回答とrubric versionだけを`judge-input.json`へ入れます。

   ```json
   {
     "judge_item_id": "item-7f3a",
     "rubric_version": "judge-v1",
     "answer": {
       "status": "completed",
       "service_estimates": [],
       "assumptions": [],
       "excluded_costs": [],
       "confidence": 0.0,
       "summary": "ここへ対象回答を機械的にコピーする"
     }
   }
   ```

   <Aside type="caution" title="選択バイアスを入れない">
     人が「良さそうな回答」だけをJudgeへ渡してはいけません。決定的ゲートを通った全回答を、元の順序を隠して一意なitem IDへ変換します。
   </Aside>

4. ### 同じ回答を3回判定する

   Judge用modelを固定して3個の新規workspaceで実行します。対象AgentとJudgeを同一modelにする場合も、その事実と理由を記録します。

   <Tabs>
     <TabItem label="Codex">
       <Command title="Judgeを3回実行" prompt="3 FRESH JUDGMENTS">

       ```bash
       export JUDGE_MODEL="使用するmodel名"
       item=workshop/manual/runs/judge/item-7f3a

       for repeat in 1 2 3; do
         judgment="$item/repeat-$repeat"
         mkdir -p "$judgment"
         cp workshop/manual/prompts/judge-v1.md "$judgment/TASK.md"
         cp workshop/manual/schemas/judge-output.schema.json \
           "$judgment/judge-output.schema.json"
         cp "$item/judge-input.json" "$judgment/judge-input.json"
         echo "$repeat" > "$judgment/repeat.txt"

         (
           cd "$judgment"
           codex exec --ephemeral --sandbox read-only \
             --model "$JUDGE_MODEL" \
             --output-schema judge-output.schema.json \
             --output-last-message judgment.json \
             - < TASK.md
         )
       done
       ```

       </Command>
     </TabItem>
     <TabItem label="Claude Code">
       <Command title="Judgeを3回実行" prompt="3 FRESH JUDGMENTS">

       ```bash
       export JUDGE_MODEL="使用するmodel名"
       item=workshop/manual/runs/judge/item-7f3a

       for repeat in 1 2 3; do
         judgment="$item/repeat-$repeat"
         mkdir -p "$judgment"
         cp workshop/manual/prompts/judge-v1.md "$judgment/TASK.md"

           cd "$judgment"

       done
       ```

       </Command>
     </TabItem>
   </Tabs>

   どちらも会話を引き継がず、各結果を別ファイルへ保存します。Claude Codeではsession persistenceと書き込み系toolを明示的に無効化します。

5. ### 3回の結果を集約する

   <ConsoleStep title="集約規則を実行前に固定" label="AGGREGATION">

   | 出力 | 集約方法 |
   |---|---|
   | 4つのscore | 各次元の中央値 |
   | `semantic_pass` | 3回中2回以上の多数決 |
   | `critical_concern` | 1回でもあれば保持 |
   | 総合合格 | `deterministic_pass AND semantic_pass` |

   </ConsoleStep>

   `workshop/manual/scripts/aggregate_judge.py`を作り、規則をコードへ固定します。

   ```python
   import json
   import sys
   from pathlib import Path
   from statistics import median

   items = [
       json.loads(path.read_text(encoding="utf-8"))
       for path in sorted(Path(sys.argv[1]).glob("repeat-*/judgment.json"))
   ]
   dimensions = [
       "assumption_clarity",
       "uncertainty_handling",
       "exclusion_clarity",
       "actionability",
   ]
   concerns = [item["critical_concern"] for item in items if item["critical_concern"]]
   result = {
       "repeats": len(items),
       "median_scores": {
           name: median(item["scores"][name] for item in items)
           for name in dimensions
       },
       "semantic_pass": sum(item["semantic_pass"] for item in items) >= 2,
       "critical_concerns": concerns,
   }
   print(json.dumps(result, ensure_ascii=False, indent=2))
   ```

   <Command title="Judge結果を集約">

   ```bash
   python workshop/manual/scripts/aggregate_judge.py \
     workshop/manual/runs/judge/item-7f3a \
     > workshop/manual/runs/judge/item-7f3a/summary.json
   ```

   </Command>

   集約後も3個の生`judgment.json`を残します。不一致が大きい回答はJudge不安定として別途レビューします。

6. ### Gold setで校正する

   人間2名が合意した最低6回答を用意します。次の境界例を含め、Judgeのfalse passを優先して調べます。

   - 数値は正しいが、仮定を明記しない
   - 情報不足を勝手に補完している
   - 長いが、第三者が式を再計算できない
   - 簡潔だが、仮定・除外・根拠が十分に追跡できる

   rubric、Judge model、prompt、推論設定のいずれかを変えたら、gold setを再実行します。

</Steps>

<Aside type="danger" title="Judgeは客観的失敗を救済しない">
  決定的ゲートが不合格なら、Judgeが3回とも高得点でも総合不合格です。Judgeにはoracleの金額を判定させず、説明品質だけを担当させます。
</Aside>

<ExpectedResult>

匿名化されたJudge入力、3回の生判定、固定した集約規則、gold set校正結果が残り、Judge自身の非決定性も監査できます。

</ExpectedResult>
