LLM Judgeは、数値の正誤を雰囲気で採点するためのものではありません。決定的ゲートを通った回答だけを対象に、コードでは決めにくい説明品質を4次元で評価します。

<Steps>

1. ### Judgeのrubricを作る

   `workshop/manual/prompts/judge-v1.md`を作ります。

   <FileCreate path="workshop/manual/prompts/judge-v1.md" lang="markdown" code={fileContent1} />

2. ### Judge出力のSchemaを用意する

   <Command title="Judge契約を準備">

   ```bash
   cp schemas/judge-output.schema.json \
     workshop/manual/schemas/judge-output.schema.json
   python -m json.tool \
     workshop/manual/schemas/judge-output.schema.json > /dev/null
   ```

   </Command>

3. ### 回答を匿名化する

   次のスクリプトを保存します。第6章の決定的ゲート通過回答を**全件**集め、順序をシャッフルし、case IDとAgentメトリクスを取り除きます。元trialとの対応表`mapping.json`はJudge workspaceへコピーしません。回答本文にmodel名などが自発的に含まれていないかも確認してください。

   <FileCreate path="workshop/manual/scripts/prepare_judge.py" lang="python" code={fileContent2} />

   <Command title="匿名Judge入力を全件生成" prompt="BASH">

   ```bash
   python workshop/manual/scripts/prepare_judge.py \
     workshop/manual/runs/no-mcp-batch-01/cfn-missing-usage \
     workshop/manual/runs/judge-batch-01
   find workshop/manual/runs/judge-batch-01 -name judge-input.json -print
   ```

   </Command>

   生成先は`workshop/manual/runs/judge-batch-01/item-＜自動ID＞/judge-input.json`です。IDを手入力する必要はありません。合格回答が0件ならここで停止し、原因を調べて新しい実験を作ります。

   <Aside type="caution" title="選択バイアスを入れない">
     人が「良さそうな回答」だけをJudgeへ渡してはいけません。決定的ゲートを通った全回答を、元の順序を隠して一意なitem IDへ変換します。
   </Aside>

4. ### 同じ回答を3回判定する

   Judge用modelを固定して3個の新規workspaceで実行します。対象AgentとJudgeを同一modelにする場合も、その事実と理由を記録します。

   <Tabs>
     <TabItem label="Codex">
       <Command title="Judgeを3回実行" prompt="3 FRESH JUDGMENTS">

       ```bash
       pricing_disable=()
       if codex mcp get aws-pricing > /dev/null 2>&1; then
         pricing_disable=(-c mcp_servers.aws-pricing.enabled=false)
       fi
       read -r -p 'Judgeに使用するモデル名: ' JUDGE_MODEL
       : "${JUDGE_MODEL:?モデル名を入力してください}"
       printf '%s\n' "$JUDGE_MODEL" > workshop/manual/runs/judge-batch-01/judge-model.txt
       for item in workshop/manual/runs/judge-batch-01/item-*; do
       test -f "$item/judge-input.json" || continue
       for repeat in 1 2 3; do
         judgment="$item/repeat-$repeat"
         if test -e "$judgment"; then
           printf '%s\n' "既存判定を保持: $judgment"
           continue
         fi
         mkdir -p "$judgment"
         cp workshop/manual/prompts/judge-v1.md "$judgment/TASK.md"
         cp workshop/manual/schemas/judge-output.schema.json \
           "$judgment/judge-output.schema.json"
         cp "$item/judge-input.json" "$judgment/judge-input.json"
         echo "$repeat" > "$judgment/repeat.txt"

         (
           cd "$judgment"
           codex exec --ephemeral --sandbox read-only \
             "${pricing_disable[@]}" \
             --model "$JUDGE_MODEL" \
             --output-schema judge-output.schema.json \
             --output-last-message judgment.json \
             - < TASK.md
         )
       done
       done
       ```

       </Command>
     </TabItem>
     <TabItem label="Claude Code">
       <Command title="Judgeを3回実行" prompt="3 FRESH JUDGMENTS">

       ```bash
       read -r -p 'Judgeに使用するモデル名: ' JUDGE_MODEL
       : "${JUDGE_MODEL:?モデル名を入力してください}"
       printf '%s\n' "$JUDGE_MODEL" > workshop/manual/runs/judge-batch-01/judge-model.txt
       for item in workshop/manual/runs/judge-batch-01/item-*; do
       test -f "$item/judge-input.json" || continue
       for repeat in 1 2 3; do
         judgment="$item/repeat-$repeat"

           printf '%s\n' "既存判定を保持: $judgment"
           continue
         fi
         mkdir -p "$judgment"
         cp workshop/manual/prompts/judge-v1.md "$judgment/TASK.md"
         cp workshop/manual/schemas/judge-output.schema.json \
           "$judgment/judge-output.schema.json"
         cp "$item/judge-input.json" "$judgment/judge-input.json"
         echo "$repeat" > "$judgment/repeat.txt"

         (
           cd "$judgment"
           claude -p --model "$JUDGE_MODEL" --output-format json \
             --strict-mcp-config --mcp-config '{"mcpServers":{}}' \
             --no-session-persistence \
             --permission-mode dontAsk \
             --tools "Read,Glob,Grep" \
             --json-schema "$(cat judge-output.schema.json)" \
             "$(cat TASK.md)" > claude-result.json
         ) && python workshop/manual/scripts/extract_claude.py \
           "$judgment/claude-result.json" "$judgment/judgment.json"
       done
       done
       ```

       </Command>
     </TabItem>
   </Tabs>

   どちらも会話を引き継がず、各結果を別ファイルへ保存します。Claude Codeではsession persistenceと書き込み系toolを明示的に無効化します。

5. ### 3回の結果を集約する

   <ConsoleStep title="集約規則を実行前に固定" label="AGGREGATION">

   | 出力 | 集約方法 |
   |---|---|
   | 4つのscore | 各次元の中央値 |
   | `semantic_pass` | 全次元3以上の合格が3回中2回以上。critical concernがあれば不合格 |
   | `critical_concern` | 1回でもあれば保持 |
   | 総合合格 | `deterministic_pass AND semantic_pass` |

   </ConsoleStep>

   `workshop/manual/scripts/aggregate_judge.py`を作り、規則をコードへ固定します。

   <FileCreate path="workshop/manual/scripts/aggregate_judge.py" lang="python" code={fileContent3} />

   <Command title="Judge結果を集約">

   ```bash
   for item in workshop/manual/runs/judge-batch-01/item-*; do
     test -f "$item/judge-input.json" || continue
     python workshop/manual/scripts/aggregate_judge.py "$item" > "$item/summary.json"
   done
   ```

   </Command>

   各itemに`repeat-1/`〜`repeat-3/`と`summary.json`ができます。判定が3件揃わなければ集約はエラーになります。集約後も3個の生`judgment.json`を残します。不一致が大きい回答はJudge不安定として別途レビューします。

6. ### Gold setで校正する

   人間2名が合意した最低6回答を用意します。次の境界例を含め、Judgeのfalse passを優先して調べます。

   - 数値は正しいが、仮定を明記しない
   - 情報不足を勝手に補完している
   - 長いが、第三者が式を再計算できない
   - 簡潔だが、仮定・除外・根拠が十分に追跡できる

   rubric、Judge model、prompt、推論設定のいずれかを変えたら、gold setを再実行します。

</Steps>

<Aside type="danger" title="Judgeは客観的失敗を救済しない">
  決定的ゲートが不合格なら、Judgeが3回とも高得点でも総合不合格です。Judgeにはoracleの金額を判定させず、説明品質だけを担当させます。
</Aside>

<ExpectedResult>

匿名化されたJudge入力、3回の生判定、固定した集約規則が残ります。gold setの作成と人間2名の合意は別途実施する発展課題です。未実施なら「未校正」と記録し、実施済みと扱わないでください。

</ExpectedResult>
