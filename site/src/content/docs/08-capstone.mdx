最後に「何となくMCPありの方が良かった」ではなく、変更点を一つに絞って比較できる実験計画へまとめます。

第6章の2つの実行例は、MCPなしでは情報不足ケース、MCPありではstatic-siteを使っています。**ケースも異なるため、この2つの成功率だけでMCPの優劣は比較できません。** この章ではまず実施済みの結果をレポートへ保存し、同じケースを両条件で測る比較計画を記録します。

<Steps>

1. ### 比較する一要因を選ぶ

   最初の比較では、prompt、model、case、反復数を固定し、MCPの有無だけを変えます。

   <ConsoleStep title="比較マトリクス" label="EXPERIMENT">

   | 条件 | Prompt | Cases | Repetitions | Tool |
   |---|---|---|---:|---|
   | A: no-mcp | agent-v1 | 同じ2ケース | 5 | なし |
   | B: pricing-mcp | agent-v1 | 同じ2ケース | 5 | AWS Pricing MCP |

   </ConsoleStep>

   no-mcpで価格が必要なケースを解かせる場合は、事前に固定した公開price snapshotをAgent入力へ追加します。MCPありだけが価格情報を持つ比較にすると、tool品質ではなく情報有無の差を測ることになります。

2. ### 実験順序と中止条件を固定する

   1. ケースとoracleを人がレビューする
   2. no-mcpで1ケース1回のpilotを行う
   3. pricing-mcpで1ケース1回のpilotを行う
   4. tool、出力、費用、秘密情報をレビューする
   5. 各ケース5回の本測定を行う
   6. 決定的ゲートを全trialへ適用する
   7. Gate通過回答を匿名化し、Judgeを3回ずつ実行する
   8. 条件別に指標と失敗taxonomyを比較する

   秘密情報、予期しない書き込み、AWS変更操作、費用上限超過、oracle漏洩、workspace外出力が一つでも見つかったら停止します。

3. ### 証跡の構成を揃える

   <Command title="構成・表示例（実行しません）" prompt="TEXT">

   ```text
   workshop/manual/
   ├── experiment.json
   ├── experiment-pricing-mcp.json  # 第4章を実施した場合
   ├── runs/no-mcp-batch-01/cfn-missing-usage/
   │   ├── experiment.json
   │   ├── trial-01/
   │   │   ├── TASK.md
   │   │   ├── answer.json
   │   │   ├── events.jsonl
   │   │   ├── exit-code.txt
   │   │   └── verdict.json
   │   └── summary.json
   ├── runs/pricing-mcp-batch-01/cfn-static-site/  # MCPあり反復
   ├── runs/judge-batch-01/<anonymous-item-id>/
   │   ├── repeat-1/judgment.json
   │   ├── repeat-2/judgment.json
   │   └── repeat-3/judgment.json
   └── report.md
   ```

   </Command>

   Agent認証、AWS資格情報、秘密を含むtranscript、MCPの一時ファイルは成果物へ含めません。

4. ### レポートに判断を書き残す

   次のテンプレートを`workshop/manual/report.md`へ保存します。「本文・Vimで作成」の方法で開き、`未記入`を実測値へ置き換えます。JSON集計は表示して読み、Markdownレポートへ結果を記入します。

   <FileCreate path="workshop/manual/report.md" lang="markdown" code={reportTemplate} />

   <Command title="レポートへ転記する集計を表示" prompt="BASH">

   ```bash
   python -m json.tool workshop/manual/runs/no-mcp-batch-01/cfn-missing-usage/summary.json
   git rev-parse HEAD
   ```

   </Command>

   条件ごとに次を記載します。

   - trial success rateとWilson 95% CI
   - caseごとのpass@kとpass^k
   - critical failureの件数とtaxonomy
   - Judge 4次元の中央値と判定不一致数
   - model、CLI、prompt、MCP package、Schema、caseのversionまたはdigest
   - 推論時間、token、概算費用、tool call
   - 改善対象をprompt／case／tool／modelのどこへ置くか

5. ### 次の変更を一つだけ決める

   JSON違反ならSchemaとprompt、価格filterの誤りならMCP利用手順、情報不足の捏造ならケースと判断規則、説明品質だけの問題ならrubricを見直します。複数を同時に変えず、新しい`experiment_id`で再測定します。

6. ### 別の人に再現してもらう

   口頭補助なしで、ケース作成、MCP接続、1 trial、5回反復、決定的採点、Judge判定まで再現できるか確認します。迷った箇所は、評価対象の問題ではなくハンズオンの不備として直します。

</Steps>

<ExpectedResult title="Workshop Complete">

専用CLIの成功画面ではなく、テストケース、prompt、MCP設定、独立trial、決定的判定、Judge判定、比較レポートを自分で説明・変更できる状態になっています。

</ExpectedResult>

</Checkpoint>

<Aside type="tip" title="評価基盤へ自動化するのは理解した後">

</Aside>
